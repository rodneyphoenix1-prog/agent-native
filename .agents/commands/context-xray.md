Run the local Context X-Ray analyzer and show the user the generated report link
plus the top warnings.

Use this command by default:

```sh
~/.agent-native/context-xray/context-xray --open $ARGUMENTS
```

If `$ARGUMENTS` is empty, analyze the current or most recent local thread. If
the user asks for a picker or all sessions, use `threads --open`. If they ask
for trends, use `trends --since 7d --open`.

`--open` opens a local HTML report file directly; there should not be a
long-running server process to monitor.

After the command finishes, summarize:

- the report link
- sessions analyzed
- the largest context bucket
- the most important warning
- two or three concrete ways to improve this thread
PHOENIX OS — MONEY ENGINE

Build a production-ready Money Engine inside Phoenix OS.

The Money Engine is NOT a static “make money online” idea database. It is an AI-powered opportunity-to-revenue execution system whose job is to continuously discover legitimate opportunities, validate them, execute them, measure results, learn from them, and loop.

CORE OBJECTIVE

Turn:

Opportunity → Validation → Offer → Prospect → Outreach → Sale → Delivery → Payment → Repeat → Automation

into a measurable daily operating loop.

Phoenix must be judged by real execution and revenue, not by the number of ideas it generates.

---

1. OPPORTUNITY RADAR

Continuously identify legitimate online business opportunities across:

- AI services
- AI automation
- Freelancing
- B2B services
- Lead generation
- Appointment setting
- Affiliate marketing
- Digital products
- Micro-SaaS
- E-commerce
- UGC/content
- YouTube/TikTok
- Remote work
- Marketplaces
- Data/information products
- Licensing
- Software
- Creator businesses
- Emerging platforms
- Other legitimate internet-business models

For every opportunity record:

- Opportunity name
- Problem being solved
- Target customer
- Existing demand evidence
- How customers currently solve it
- Potential offer
- Acquisition method
- Startup cost
- Skills required
- Time to first potential customer
- Revenue model
- Estimated margin
- Scalability
- Competition
- Platform/payment availability
- Regulatory/legal considerations
- Scam/fraud risk
- Evidence/source
- Date discovered

Never present an opportunity as guaranteed income.

---

2. OPPORTUNITY FILTER

Create an objective scoring/filtering system based on:

- Demand evidence
- Accessibility
- Starting capital
- Time-to-first-sale
- Profit potential
- Recurring revenue potential
- Scalability
- AI leverage
- Automation potential
- Competition
- Operational complexity
- Risk

Do NOT simply generate a huge list.

Prioritize opportunities that can realistically move toward a paying customer.

Allow Phoenix to mark opportunities:

TEST → ACTIVE → SCALE → PAUSE → KILL

---

3. EXPERIMENT ENGINE

Every selected opportunity becomes a measurable experiment.

For each experiment Phoenix must define:

Hypothesis

What do we believe customers will pay for?

Customer

Exactly who are we targeting?

Offer

What are we selling?

Price

What is the proposed price?

Acquisition

How will prospects be found?

Daily Action

Exactly what must happen today?

Success Metric

What measurable result determines whether the experiment works?

Kill Criteria

What evidence means we should stop?

Scale Criteria

What evidence means we should increase execution?

Never allow Phoenix to endlessly “research” an opportunity without taking action.

---

4. CUSTOMER ACQUISITION ENGINE

Create a prospect pipeline:

Prospect → Contacted → Responded → Qualified → Offer Sent → Negotiating → Won → Lost → Follow-up

Track:

- Name/business
- Contact
- Source
- Problem
- Offer
- Date contacted
- Last contact
- Next follow-up
- Status
- Estimated value
- Actual revenue
- Notes

Generate personalized outreach based on the prospect and offer.

Avoid spam, deception, fake identities, fabricated testimonials, or misleading claims.

---

5. SALES ENGINE

Track:

- Leads
- Conversations
- Qualified prospects
- Offers
- Closed deals
- Revenue
- Conversion rates
- Average deal value
- Customer acquisition cost
- Profit

Phoenix should identify bottlenecks.

Example:

100 prospects → 20 replies → 5 calls → 2 offers → 0 sales

The system should identify where the funnel is failing and recommend a specific experiment to fix that stage.

---

6. DELIVERY ENGINE

After a customer pays, automatically create a delivery workflow.

Track:

Paid → Requirements → Production → Review → Delivered → Retention → Upsell

Where possible, use connected AI tools and automation to reduce repetitive work.

Human approval should remain available for important external actions.

11. APPROVAL SYSTEM

Phoenix may research, analyze, prepare drafts, organize information and create execution plans autonomously.

Require human approval before:

- Spending money
- Making financial commitments
- Sending sensitive communications
- Entering contracts
- Publishing potentially consequential content
- Making irreversible account changes
- Moving funds
- Any action requiring legal authorization

Show an approval queue inside the dashboard.

---

12. ANTI-SCAM / TRUTH MODE

Build a permanent RED TEAM MODE.

Before Phoenix recommends an opportunity, test:

- Is there verifiable demand?
- Who actually pays?
- What are the real costs?
- What are the platform restrictions?
- Is the revenue claim realistic?
- Are there hidden fees?
- Is this dependent on referrals?
- Is it legally permitted?
- Is it available in the user's market?
- Is there evidence of real customers?
- What could make this fail?
- What information is uncertain?

Never describe something as:

“guaranteed”
“easy money”
“passive income”
“risk-free”
“100% working”

unless the statement is literally supportable.

Separate:

FACT → EVIDENCE → ASSUMPTION → EXPERIMENT

13. MONEY-FIRST PRIORITY

Phoenix must understand:

Ideas are not results.

Research is not revenue.

Followers are not necessarily customers.

Revenue is not profit.

Automation is not a business.

The system should therefore prioritize measurable movement toward:

CUSTOMER → PAYMENT → PROFIT → REPEATABILITY → SCALE
